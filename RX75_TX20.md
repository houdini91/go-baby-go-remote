### 🔄 Pairing Process
* **Remote pairing mode**
  When entering pairing mode, the remote transmits on a slightly different channel (\~2.44 GHz) at a noticeably slower burst rate.

  ```
  c710f55cccccca518cbb4a850
  ```

* **Car response** (confirmed via HackRF)
  The car appears to respond on \~2.405 GHz using a similar burst format:

  ```
  c710f55cccccc5a77ae2cbc98500
  ```

* **Pairing completion**
  The remote's LED indicates a successful pair. Immediately after this, the remote begins transmitting on the **normal data channel** (\~2.453 GHz), using a valid “speed” control packet:

  ```
  c710f553475eeaa085da650
  ```

## Frame layout assumption

| Field        | Size     | Example (Hex) | Notes                                                               |
| ------------ | -------- | ------------- | ------------------------------------------------------------------- |
| PREAMBLE     | variable | `c7 10 f5 5`  | synchronization; not part of logical payload. |
| DEVICE ID    | 3 Byte  | `34 75 ee` | Constant per remote/car pair (your car’s ID).                       |
| HEADER       | 1 BYTE  | `aa` |  ???                                                                         |
| OPCODE       | 1 Byte  | `18`          | High nibble = direction mask: 0x1=LEFT, 0x2=RIGHT, 0x4=FORWARD, 0x8=BACK; combos additive (0x5=LEFT+FWD, 0x6=RIGHT+FWD, 0x9=LEFT+BACK, 0xA=RIGHT+BACK). <br/>Low nibble = speed flags: S1=0x8, S2=0x4, S3=0xC (S1|S2)|
| CMD          | 1 Byte   | `4f`          | Direction + speed bits. Some mirrored.                              |
| TAIL         | 2 Byte   | `9750`        | Likely checksum or CRC over previous 

#### 🧠 `OP` Byte — Bit Layout and Meaning

The **`OP` (OPCODE) field** is **1 byte wide (8 bits)** and encodes two key pieces of information:

```
OPCODE: [ d3 d2 d1 d0 | s3 s2 s1 s0 ]
          direction     speed flags
```

| Bits (MSB→LSB)        | Purpose            | Notes                                                                                                                                              |
| --------------------- | ------------------ | -------------------------------------------------------------------------------------------------------------------------------------------------- |
| **b7..b4 (`d3..d0`)** | **Direction mask** | Bitmask (additive): `0x1=LEFT`, `0x2=RIGHT`, `0x4=FORWARD`, `0x8=BACK` → e.g., `0x5=LEFT+FWD`, `0x6=RIGHT+FWD`, `0x9=LEFT+BACK`, `0xA=RIGHT+BACK`. |
| **b3..b0 (`s3..s0`)** | **Speed nibble**   | RX57 mapping: **S1 = `0x8` (`1000`)**, **S2 = `0x4` (`0100`)**, **S3 = `0xC` (`1100` = `S1 \| S2`)**.                                              |


| Direction Combo | Direction Mask (hex) | Bitwise OR         | Resulting OP High Nibble | Example OP (S1 / S2 / S3) |
| --------------- | -------------------- | ------------------ | ------------------------ | ------------------------- |
| LEFT            | `0x1`                | —                  | `0x1`                    | `0x18 / 0x14 / 0x1C`      |
| RIGHT           | `0x2`                | —                  | `0x2`                    | `0x28 / 0x24 / 0x2C`      |
| FORWARD         | `0x4`                | —                  | `0x4`                    | `0x48 / 0x44 / 0x4C`      |
| BACK            | `0x8`                | —                  | `0x8`                    | `0x88 / 0x84 / 0x8C`      |
| LEFT + FORWARD  | `0x1`, `0x4`         | `0x1 \| 0x4 = 0x5` | `0x5`                    | `0x58 / 0x54 / 0x5C`      |
| RIGHT + FORWARD | `0x2`, `0x4`         | `0x2 \| 0x4 = 0x6` | `0x6`                    | `0x68 / 0x64 / 0x6C`      |
| LEFT + BACK     | `0x1`, `0x8`         | `0x1 \| 0x8 = 0x9` | `0x9`                    | `0x98 / 0x94 / 0x9C`      |

## 📡 Packet (“burst”) cadence — RX23 @ 2.453 GHz

Measurements from your note:

* **Full short‑press burst:** **~1.11 s**
* **Packet on‑air time:** **~865.5 µs** (~0.866 ms)
* **Between packets (gap):** **~11.15 ms**
* **Start‑to‑start:** **~12.05 ms** ⇒ **~83.0 Hz**

What this means:

* While a button is **held**, the remote repeats the drive packet at **~83 pkts/s**.
* On **release**, it switches to **PARK/NEUTRAL** immediately but continues at the same cadence for a brief dwell, so short presses still appear as a burst in URH.
* The car moves on the first valid *drive* frame and stops shortly after the last one (either due to *PARK* frames or an internal watchdog timeout).

```
time ──▶ [drive][drive][drive]……(release)→[PARK][PARK]…[PARK]
```
